## 迭代目标

将 BeatMeter 从单一节拍器工具升级为“节拍器 + 健身指导”双模块产品，在保持节拍器核心体验稳定的前提下，新增健身指导能力、动作内容组织、器械说明、示意图能力、品牌升级及关于/反馈入口。

### 背景动机

当前产品的核心能力集中在节拍器，但目标用户对训练陪伴、动作参考、器械使用说明等健身场景需求逐步增加。
v2.0.0 的目标不是一次性做成完整健身社区或专业训练平台，而是在现有产品基础上完成方向升级：
1. 明确形成“节拍器”与“健身指导”两大模块；
2. 提供可用、可理解、可持续扩展的健身内容结构；
3. 补充品牌表达、关于说明和反馈渠道，提升产品完整度；
4. 控制 AI 图片、内容准确性、命名改造等高风险范围，避免版本失控。

### 可执行默认值

若立项时以下信息仍未最终确认，本文默认按以下方案推进：
- **负责人**：统一记为“待定”；
- **训练记录**：默认仅记录本地训练时长，不做账号体系与云同步；
- **反馈机制**：默认采用外链表单或邮箱反馈，不自建工单系统；
- **AI 图片能力**：默认优先提供系统预置动作示意图；用户自定义 AI 生成功能可灰度上线或延期；
- **App 更名**：默认先完成应用内名称、文案、图标/启动露出调整；包名/商店主体信息变更视发布条件决定是否同步。

## 需求列表

### 需求 1：健身指导模块入口与信息架构
- **类型**：🆕 新功能
- **优先级**：P0
- **负责人**：待定
- **描述**
  在现有 App 中新增“健身指导”一级入口，与“节拍器”并列成为两大核心模块。健身指导首页需具备清晰的信息架构，至少包含训练分类入口、器械说明入口、动作示意图入口/区域，以及训练时长记录入口或启动能力。
  本需求为 v2.0.0 的结构性基础，属于**本次必须交付**。
- **验收标准**
  - [ ] App 首页或主导航中可明确区分“节拍器”和“健身指导”两大模块
  - [ ] 用户可在 1 次点击内进入健身指导首页
  - [ ] 健身指导首页至少包含“训练分类”“器械说明”“动作示意图/示范图”三类核心入口
  - [ ] 页面文案与导航命名统一，不出现旧结构残留或歧义入口
  - [ ] 从健身指导模块返回节拍器模块路径清晰，无死路或迷失导航

### 需求 2：训练分类、动作详情与训练时长记录
- **类型**：🆕 新功能
- **优先级**：P0
- **负责人**：待定
- **描述**
  健身指导模块需建立基础训练内容体系，至少覆盖**胸、肩、背、腿**四大分类。每个分类下提供动作列表，动作详情页展示动作名称、目标肌群、动作步骤、常见错误、适用人群/难度、安全提示等信息。
  同时支持用户开始一次训练并记录本次训练时长，默认仅记录单次训练时长与最近训练结果，不要求训练计划编排。
  本需求为**本次必须交付**。
- **验收标准**
  - [ ] 健身指导模块至少提供胸、肩、背、腿四大分类
  - [ ] 每个分类下至少有可浏览的动作列表
  - [ ] 动作详情页至少包含：动作名称、目标肌群、动作步骤、安全提示
  - [ ] 动作详情页明确标注“内容仅供训练参考，非医疗建议”或同等级提示
  - [ ] 用户可开始/结束一次训练时长记录
  - [ ] 训练结束后可看到本次训练时长结果
  - [ ] 重启 App 后，最近一次训练结果或基础训练记录仍可读取（本地存储）

### 需求 3：常用器械说明
- **类型**：🆕 新功能
- **优先级**：P1
- **负责人**：待定
- **描述**
  新增器械说明内容区，帮助用户理解常用健身器械的基础使用方式、适用部位、注意事项和新手提示。
  **建议本次最低交付范围**为常见高频器械的基础说明（如哑铃、杠铃、史密斯机、龙门架、卧推椅、腿举机、划船机、拉力器等），更完整器械库可后续扩展。
  本需求为**建议交付**；若周期紧张，可保留高频器械的最小集合，扩展器械数量可降级。
- **验收标准**
  - [ ] 提供独立“器械说明”入口或在健身指导内可明确访问
  - [ ] 至少覆盖 8 个常见器械的说明内容
  - [ ] 每个器械说明至少包含：器械名称、适用训练部位、基础使用方法、注意事项
  - [ ] 新手能在 3 步以内到达任一器械详情页
  - [ ] 器械内容与动作内容之间存在可理解的关联关系（如相关动作推荐或返回路径）

### 需求 4：动作示意图能力（系统图优先，AI 生成为增强项）
- **类型**：🆕 新功能
- **优先级**：P1
- **负责人**：待定
- **描述**
  为动作详情补充示意图能力，优先支持系统提供的标准动作示意图，提升动作理解效率。
  在此基础上，探索加入用户自定义 AI 动作图生成功能，用于生成特定角度、特定器械或特定动作的示意图。考虑到成本、时延、审核和错误引导风险，本版本建议采用“**系统图必须有，用户自定义 AI 生成可灰度或延期**”的策略。
  本需求为**部分必须交付**：系统预置示意图为推荐 MVP，完整 AI 自定义生成可降级。
- **验收标准**
  - [ ] 重点动作详情页可展示至少 1 张系统预置动作示意图
  - [ ] 示意图与动作名称、动作说明可对应，不出现明显错配
  - [ ] 若开放 AI 生成入口，需明确展示“生成中/失败/重试”状态
  - [ ] 若开放 AI 生成入口，需对生成次数、等待时长或使用说明做显式提示
  - [ ] 若 AI 生成失败，不影响用户继续查看系统预置内容
  - [ ] 不允许直接将未经说明的 AI 生成结果表达为专业医疗或训练结论

### 需求 5：节拍器模块体验优化
- **类型**：🔧 优化
- **优先级**：P0
- **负责人**：待定
- **描述**
  在产品升级为双模块后，节拍器仍需保持核心入口与使用效率，避免因新模块加入导致原有体验退化。
  本次优化重点建议聚焦：入口清晰、播放控制稳定、BPM 调节顺畅、设置状态可保留、视觉反馈更明确。
  本需求为**本次必须交付**。
- **验收标准**
  - [ ] 用户可从首页或主导航快速进入节拍器
  - [ ] 节拍器播放、暂停、停止不因新增模块而出现明显回归
  - [ ] BPM 调整、点击节奏、设置读取与保存流程可正常使用
  - [ ] 当前拍/节拍状态视觉反馈清晰，不因 UI 改版而弱化
  - [ ] 从健身指导模块切回节拍器后，基础状态管理符合预期（不出现明显异常残留或崩溃）

### 需求 6：App 更名与品牌露出调整

  - [ ] 若新名称尚未最终确认，代码与文案层采用可替换占位方案，不阻塞开发
  - [ ] 更名前后不影响现有核心功能使用
  - [ ] 若本版本不调整包名/商店信息，需在版本说明中明确记录为延期项

## 非目标（本次不包含）

- 不建设完整的个性化训练计划系统（如周期计划、组数/次数自动编排、智能推荐课表）
- 不建设用户账号体系、云同步、跨设备训练数据同步
- 不建设社交社区、打卡排行、好友互动、教练服务市场
- 不建设饮食管理、热量统计、体脂/体重管理等完整健康管理能力
- 不提供视频课程、直播教学或真人动作识别纠错
- 不将 AI 图片生成扩展为照片编辑、真人换脸、用户形象定制等高风险能力
- 不在本次承诺专业医疗建议、康复建议或替代线下教练指导
- 不默认同步完成所有商店层面的品牌主体变更、包名迁移、历史评论/评分迁移
- 不建设独立后台管理系统；内容维护默认可先通过静态配置或轻量内容源支持

## 技术说明

### 1. 实现边界与推荐默认方案
- 现有项目为 Expo + React Native 应用，v2.0.0 建议在当前单应用结构内扩展“双模块”导航，不建议本次升级为多端分体架构。
- 训练记录、节拍器设置等数据默认采用本地存储；**本版本不引入账号登录与云端同步**，以降低复杂度。
- 反馈机制默认采用邮箱或外链表单，避免新增后端服务依赖。
- 健身内容建议优先以结构化静态内容或本地配置方式交付，降低内容管理成本。

### 2. AI 图片生成成本、时延与审核风险
- AI 图片生成存在第三方服务成本，需提前明确计费方式、免费额度、日调用上限与熔断策略。
- AI 生成存在明显等待时延，需设计生成中、失败、重试、超时与降级展示方案。
- AI 结果可能出现动作错误、器械错配、肢体畸形、暴露不合规或误导性内容，需配置审核策略或限制 prompt 范围。
- 若无法保证稳定性，建议 v2.0.0 先以**系统预置示意图**为主，用户自定义 AI 生成功能采用灰度开关或延期至后续版本。
- 若开放 AI 生成，建议增加免责声明：生成结果仅作示意参考，实际训练请结合文字说明与安全提示。

### 3. 动作指导内容准确性与安全提示
- 动作内容与器械说明必须经过人工校对，不应完全依赖 AI 自动生成直接上线。
- 每个动作详情应包含基础安全提示，尤其针对新手、负重训练、器械使用风险动作。
- 建议增加统一说明：内容用于一般训练参考，不构成医疗、康复或专业教练指导。
- 若后续引入更多训练内容，需明确内容审核责任人或校对流程，否则内容扩展会带来持续风险。

### 4. App 更名影响与依赖提醒
- 更名影响范围不仅包括应用标题，还包括：图标、启动页、关于页、应用内文案、分享文案、商店简介、隐私政策/说明页面等。
- 若同步调整包名/应用标识（Android applicationId、iOS bundle identifier），可能影响安装升级路径、商店发布记录、已有用户覆盖安装与第三方配置。
- 建议将“**应用内名称更新**”与“**包名/商店主体变更**”拆分决策；前者可在 v2.0.0 必做，后者视发布策略决定。
- 若历史数据依赖旧命名字段，需评估是否存在迁移逻辑或兼容问题。

### 5. 数据存储边界
- **训练记录**：默认只记录本地训练时长与最近结果，不保存完整训练历史分析，不做云同步。
- **设置数据**：延续现有节拍器设置本地持久化方式，新增健身模块相关偏好时应避免破坏现有存储兼容性。
- **反馈数据**：默认不在 App 内部存储完整反馈工单，仅跳转到外部渠道或调用系统邮件能力。
- **AI 图片数据**：若启用生成能力，需明确是否缓存结果、缓存多长时间、是否允许离线查看，以及是否涉及用户输入内容的隐私问题。

### 6. 验证与发布提醒
- 当前仓库未配置自动化测试，本版本需重点补充手动验收路径，尤其是模块切换、内容浏览、节拍器稳定性、训练时长记录、反馈跳转与异常降级。
- 涉及 AI 服务、外链反馈、应用更名等改动时，需分别验证弱网、失败、未配置、被限流等异常场景。
- 若商店信息同步更新，需预留素材制作、审核等待与文案合规检查时间。

## 版本范围建议

### MVP 必做范围（建议锁定）
- 健身指导模块一级入口与双模块信息架构
- 胸 / 肩 / 背 / 腿四大训练分类
- 基础动作详情页（含动作步骤、目标肌群、安全提示）
- 单次训练时长记录与本地保存
- 节拍器模块核心体验不回退，并完成必要优化
- App 应用内名称与主要品牌露出更新
- 关于页基础信息（免费说明、AI 辅助生成但经人工审核、博客入口、至少一种反馈方式）
- 系统预置动作示意图的最小可用方案

### 可延期项（建议作为降级预案）
- 用户自定义 AI 动作图生成
- 更完整的大规模器械库扩展
- 复杂反馈系统（站内工单、反馈历史、状态追踪）
- 包名 / 商店主体 / 历史安装迁移等高影响更名项
- 完整训练历史统计、训练计划编排、个性化推荐
- AI 图片结果缓存、收藏、分享等增强能力

### 优先级建议汇总
- **P0（本次必须交付）**：需求 1、需求 2、需求 5、需求 6（应用内更名部分）
- **P1（建议交付，可按资源降级）**：需求 3、需求 4、需求 7
- **P2（本次不建议纳入）**：个性化训练计划、账号云同步、社区/课程、复杂 AI 能力扩展
